# 지출계획 · money-demo

소비 전에 앞으로 쓸 돈을 적고 **필수·선택·보류**로 판단하는 개인 지출계획 데모입니다. 기획·화면 설계·프론트엔드 구현을 보여주기 위한 별도 정적 버전이며, 원본 프로젝트는 변경하지 않았습니다.

## 실행

1. ZIP을 풀고 `money-demo/index.html`을 Chrome 또는 Edge 등 최신 브라우저로 엽니다.
2. 수입을 입력한 다음 계획을 추가합니다.

Docker, DB, 백엔드, React, Next.js, TypeScript 컴파일, npm 설치, 빌드, 외부 CDN이 필요하지 않습니다. 모든 실행 파일은 이 폴더 안에 있습니다. 별도 라우팅 설정 없이 폴더를 정적 HTTP/HTTPS 호스팅에 그대로 제공할 수 있습니다. 로컬 확인을 위해 이미 사용하는 편집기의 정적 미리보기 기능을 이용해도 됩니다. Node나 Python 설치는 사용 조건이 아닙니다.

직접 파일 열기(`file://`)에서는 브라우저 정책에 따라 저장이 제한되거나 파일 경로별로 달라질 수 있어 **저장 지속성을 보장하지 않습니다**. 개인 저장을 계속 사용할 때는 동일한 정적 HTTP/HTTPS 주소에서 사용하세요. 직접 파일 열기와 HTTP 주소 사이에 데이터가 자동 이동하지는 않습니다. JSON 백업으로 옮길 수 있습니다.

## 구성

- `index.html`: 단일 진입점, 홈·계획·수입 폼의 HTML 템플릿
- `css/style.css`: 원본 화면의 색상·타이포·너비·간격·카드·폼·반응형 스타일을 일반 CSS로 이식
- `js/calculations.js`: bigint 금액, 서울 기준 현재 월, 날짜 검증, 수입·계획·예상 잔액·편집 미리보기
- `js/storage.js`: 공통 데이터 검증, JSON 변환, localStorage 접근과 오류 처리
- `js/main.js`: 해시 라우팅, 화면 상태, 입력·수정·취소·복구, 백업 UI

외부 이미지·웹폰트를 내려받지 않습니다. 시스템 글꼴을 사용하며 원본 월 이동 SVG를 인라인으로 포함합니다. CSS/JS는 일반 파일로 로드하여 로컬 JSON fetch나 모듈 서버가 필요하지 않습니다.

## 구현 범위

- 이전·다음 월과 과거 월 조회
- 정기/비정기 수입 등록·수정·취소, 취소 직후 스낵바에서 20초 동안 되돌리기
- 비정기 예정 수입의 계산 포함 선택, 입금 완료
- 계획 등록·수정·취소·취소 목록에서 복구
- 홈의 판단별 계획 목록·계산 기준 수입·세 가지 예상 잔액
- 저장된 해당 월 데이터를 사용한 계획 미리보기. 편집 대상의 원래 금액은 먼저 제외
- 브라우저 개인 저장, JSON 내보내기·검증/확인 후 전체 교체, 확인 후 앱 데이터 초기화

실제 지출·계획 완료·월간 요약·인증·기기 간 동기화·사용자 카테고리 관리는 제외했습니다. 원본 홈에 있던 완료·요약 버튼은 비활성 상태로 유지합니다. 기본 카테고리 11개의 이름·순서와 seed의 고정 ID를 사용합니다.

## 화면 주소

- `#/home?month=2026-11`
- `#/incomes?month=2026-11`
- `#/plans/new?month=2026-11`
- `#/plans/edit?id=항목ID&month=2026-11`

브라우저 기본 해시 이력을 사용합니다. 잘못된 월은 서울 기준 현재 월로 바꾸고, 모르는 화면은 홈으로 바꿉니다. 없는 ID·다른 월·취소 항목의 편집은 안내 후 홈으로 돌아갈 수 있습니다.

## 계산 규칙

원본 `src/domain/calculations.ts`, `money.ts`, `month.ts`, `plan-draft.ts`와 기획 문서의 이번 데모 범위 규칙을 이식했습니다. 실제 지출 계산 함수는 이번 범위에 추가하지 않았습니다.

| 종류 | 상태 | 적용 날짜 | 계산 |
| --- | --- | --- | --- |
| 정기 | 예정 | expectedDate | 기본 포함 |
| 정기 | 입금 완료 | depositedDate | 기본 포함 |
| 비정기 | 예정 | expectedDate | 기본 제외, 명시적으로 선택한 항목만 선택 포함 |
| 비정기 | 입금 완료 | depositedDate | 기본 포함, 선택 포함 해제 |
| 모든 수입 | 취소 | 합계에 사용하지 않음 | 제외 |

예정일이 11월 30일이고 입금일이 12월 1일이면, 정기·비정기 모두 예정 상태는 11월, 입금 완료 후는 12월입니다. 입금 완료 시 같은 항목을 갱신하며 별도 수입을 추가하지 않습니다. 취소 직후 되돌리기는 이전 상태와 포함 선택을 복구합니다.

계획은 `planMonth`에 귀속되고 예정 상태만 차감합니다. 지출예상일을 입력했다면 계획 월 안의 날짜여야 합니다. 필수는 세 잔액 모두, 선택은 두 번째·세 번째, 보류는 세 번째 잔액만 차감합니다. 부족 금액을 0원으로 바꾸지 않습니다.

입력 한도는 **1~999,999,999,999원**, 합계 한도는 signed int64 **-9,223,372,036,854,775,808~9,223,372,036,854,775,807**입니다. 금액 계산은 bigint로 수행합니다.

## 저장과 복구

앱 전용 키는 `money_set:demo:data`, `schemaVersion`은 `1`입니다.

```json
{"app":"money_set","schemaVersion":1,"incomes":[],"plans":[]}
```

금액은 `"150000"` 같은 정수 문자열이며 계산 경계에서 bigint로 복원합니다. 합계·잔액은 저장하지 않습니다. 항목은 고정 UUID를 가지며 등록 재시도에도 같은 ID를 사용합니다.

최초 읽기가 끝나기 전에는 쓰지 않습니다. 변경 후보를 전체 검증하고 저장에 성공한 경우에만 화면 상태를 바꿉니다. 저장 실패 시 기존 데이터와 입력을 유지하고 재시도할 수 있습니다. 읽을 수 없는 저장 데이터는 자동 삭제·덮어쓰기하지 않으며 원문 내보내기·다시 읽기·검증된 백업 복구·확인 후 초기화 경로를 제공합니다. 미지원 버전도 동일하게 쓰기를 차단하며 자동 변환하지 않습니다.

데이터 관리에서 JSON 백업을 내보낼 수 있습니다. 불러오기는 중복 ID, 날짜, 상태, 카테고리, 금액, 이름·메모 길이, 구조·버전, 관련 필드 조건과 계산 범위를 검증한 뒤 **모든 월의 전체 교체**를 확인받습니다. 불러오기 파일은 5MB 이하입니다. 제목·메모는 HTML로 해석하지 않고 텍스트로 표시합니다.

초기화는 확인 후 앱 전용 키만 제거합니다. 다른 앱의 저장 키는 건드리지 않습니다. 다중 탭의 저장 변경을 감지하면 편집 저장을 막고 재읽기를 안내할 뿐, 동시 저장의 완전한 충돌 방지·병합은 지원하지 않습니다.

브라우저·프로필·주소(프로토콜/호스트/포트)별로 저장 공간이 다릅니다. 브라우저 데이터 삭제, 시크릿 창 종료, 주소 변경 등에 따라 데이터가 사라지거나 보이지 않을 수 있습니다. 계정·서버 백업은 없으므로 필요한 내용은 JSON으로 보관하세요.

## 검증 결과와 한계

자동 검증 도구·테스트 데이터·임시 HTTP 서버는 이 전달 폴더에 포함하지 않았습니다.

- JavaScript 세 파일의 구문 검사 통과
- 계산·저장 자동 검사 52/52 통과
- 원본 TypeScript 계산과 결정적 500개 데이터셋을 각각 두 달에 대해 대조하여 결과 일치
- 기본 예제: 계산 기준 수입 3,300,000원 → 예상 잔액 1,800,000원 / 1,300,000원 / 1,000,000원
- 정기/비정기 × 예정/입금 완료의 서로 다른 월 날짜 사례 통과
- 판단별 차감, 편집 대상 중복 제외, 취소·삭제 제외, 복구, 음수, 윤년·연말, bigint 정확성·int64 범위 검사 통과
- 모의 저장소에서 최초 읽기 전 쓰기 방지, 저장 후 새 인스턴스 복원, 공간 부족·접근 거부, 손상·미지원 버전 보존, 초기화의 다른 키 보존, JSON 왕복·잘못된 가져오기 데이터 거부 통과
- 정적 HTTP에서 HTML·CSS·JS 응답 200 및 로컬 파일과 내용 일치. 해시 경로 직접 요청도 같은 index 응답 확인
- 정적 코드 확인: 외부 실행 리소스·데이터 저장 네트워크 코드 없음, localStorage 접근은 storage.js에만 존재, 사용자 데이터의 HTML 삽입 없음

**실제 브라우저 검증은 완료하지 못했습니다.** Windows 브라우저 제어 도구가 현재 URL을 확인하지 못해 정책상 제어를 중단했습니다. 원본/새 화면의 360px·데스크톱 비교, 실제 가로 넘침, 키보드·포커스·오류 읽기, file:// 화면·기본 동작, HTTP 브라우저에서 저장·새로고침·뒤로가기, 파일 다운로드/불러오기 클릭, 콘솔·실제 네트워크 관찰은 미검증입니다. 모의 저장소 재읽기를 브라우저 저장 지속성 검증으로 간주하지 않습니다. 원본의 계산 테스트·소스는 유지했습니다.

## 짧은 검수 순서

1. index.html을 열어 월 이동 → 수입 입력 → 정기 예정 수입 3,000,000원 등록.
2. 비정기 예정 100,000원은 기본 제외되는지 확인하고 계산 포함 선택. 입금 완료로 바꿔 총액이 중복 증가하지 않는지 확인.
3. 계획을 필수 1,500,000원·선택 500,000원·보류 300,000원 등록하고 미리보기와 홈 잔액 대조.
4. 계획 금액·판단 수정 → 취소 → 취소 목록 복구. 수입 취소 직후 스낵바 되돌리기.
5. 다른 월로 이동해 분리 확인. 예정일 11월 30일/입금일 12월 1일인 수입의 월 이동 확인.
6. 같은 HTTP 주소에서 새로고침·재접속해 저장 유지 확인.
7. JSON 내보내기 → 초기화 확인 취소 → 초기화 적용 → 백업 불러오기 확인 취소/적용. 잘못된 파일은 거부되고 기존 데이터가 유지되는지 확인.
8. 360px·데스크톱에서 긴 이름·메모·큰 금액, 키보드 탭 이동·오류 포커스, 뒤로가기·직접 주소 진입 확인.
